# 배포 안내 — 컨테이너(웹 + 워커)

이미지 하나(Python 3.12 + Node 20 + kordoc 4.24.59), 서비스 둘, 볼륨 하나로 어느 호스팅에든 올린다(ADR-046). 호스팅 위치는 아직 정하지 않았다(I-07).

| 서비스 | 하는 일 | 명령 |
|---|---|---|
| `web` | 수요자 화면·운영 화면·API | `gunicorn -w 2 -b 0.0.0.0:8000 wsgi:app` (`AUTOMATION_SCHEDULER=0`) |
| `worker` | 예약 실행: 수집 → 첨부 글자 → 분류 → 표준 필드 | `flask --app run automation-daemon` |
| 볼륨 `gongmo-data:/data` | SQLite(`gongmo.db`), 첨부(`attachments/`), 내보내기 | 두 서비스가 같이 쓴다 |

> SQLite(WAL)는 **같은 호스트의 같은 볼륨**에서만 안전하다. 웹과 워커를 다른 호스트로 나누거나 웹을 여러 대 띄우려면 Postgres와 객체 저장소로 옮겨야 한다(ADR-046). Vercel 같은 서버리스는 파일을 저장할 수 없고 백그라운드 실행이 없어 맞지 않는다.

## 1. 빌드·실행

```bash
cp .env.example .env          # 아래 2장대로 채운다
docker compose build
docker compose up -d
docker compose exec web flask --app run set-admin-password     # 관리자 비밀번호(안 하면 /admin이 503)
```

- 확인: `http://<호스트>:8000`이 200, `docker compose exec worker kordoc --version`이 4.24.59, `docker compose logs worker`에 '예약 실행기를 시작합니다'.
- `web`은 `wsgi.py`에서 `SECRET_KEY`를 검사한다. 비었거나 기본값이거나 32자보다 짧으면 뜨지 않는다.

## 2. 운영 `.env`

| 키 | 값 |
|---|---|
| `SECRET_KEY` | 32자 이상 임의 값: `python -c "import secrets; print(secrets.token_hex(32))"` |
| `ADMIN_PASSWORD_HASH` | `set-admin-password`가 채운다(직접 적지 않음) |
| `ADMIN_COOKIE_SECURE` | https로 서비스하면 `true` |
| `TRUSTED_PROXY_HOPS` | 로드밸런서·nginx 뒤면 `1`(로그인 잠금·순방문이 실제 접속 주소로 셈) |
| `PUBLIC_SHOW_ENDED` | 운영은 `0` 권장(마감 공고를 기본 목록에서 뺌) |
| `CLAUDE_API` | Claude API 키. 비어 있으면 분류·API 보완 단계는 '키 없음'으로 건너뛴다 |
| `CLAUDE_MODEL` | `claude-sonnet-5-5` — **하이픈 표기**(점 표기는 모델 ID가 아니다) |
| `CLAUDE_MODEL_EFFORT` | `low`(검증한 값. 올리면 비용·시간이 는다) |
| `CLAUDE_FALLBACKS` | `1`(동기 호출에서 거절되면 서버가 대체 모델로 답함, ADR-049) |
| `KORDOC_ENABLED` · `KORDOC_TIMEOUT` | `1` · `60`(큰 PDF가 잦으면 늘린다) |

`DATA_DIR`·`ATTACHMENT_DIR`·`EXPORT_DIR`·`KORDOC_CMD`는 compose가 `/data/…`와 `kordoc`으로 덮어쓴다(.env 값보다 우선).

## 3. 기존 DB·첨부 옮기기

이미 수집한 데이터가 있으면 볼륨에 복사한 뒤 띄운다. 첨부의 `file_path`는 `ATTACHMENT_DIR` 기준 상대경로라 폴더째 옮기면 된다.

```bash
docker compose build
docker compose run --rm --no-deps --user root -v "$PWD/data:/src:ro" --entrypoint sh web \
  -c "cp -a /src/gongmo.db /src/attachments /data/ && chown -R app:app /data"
docker compose up -d
```

옮길 때는 원본에서 앱을 멈추거나 `sqlite3 data/gongmo.db ".backup data/gongmo-copy.db"`로 만든 사본을 쓴다(WAL 파일이 따로 있어 실행 중 파일 복사는 깨질 수 있다).

## 4. 백업

```bash
docker compose exec web python -c "import sqlite3; s=sqlite3.connect('/data/gongmo.db'); d=sqlite3.connect('/data/backup-$(date +%Y%m%d).db'); s.backup(d)"
docker compose cp web:/data ./backup-data      # DB 백업 파일과 첨부 폴더
```

이미지에 `sqlite3` 명령은 없으므로 Python의 `backup()`을 쓴다. 첨부 폴더는 용량이 크니 증분 복사(rsync 등)를 권한다.

## 5. kordoc 버전 올리기

kordoc은 변경이 잦아 버전을 고정했다(ADR-050). 올릴 때는:

1. 로컬에서 `KORDOC_CMD="npx -y kordoc@<새 버전>"`으로 정답표 표본(`plan/validation/gold/gold_notes.md`, 핸드오프 부록 A 40건 포함)의 첨부를 다시 읽는다: `flask --app run attach-text --any-body --no-download --redo --ann-id …` → `extract-fields --redo --ann-id …`.
2. `python plan/validation/eval_fields.py --pred db --name kordoc-<버전>`으로 지표를 내고 현재 버전 결과(`report-db-rules.md`)와 비교한다.
3. 나빠지지 않으면 `Dockerfile`의 `kordoc@4.24.59`와 `config.py`·`.env.example`의 기본 `KORDOC_CMD`를 함께 바꾼다.

## 6. 배포 뒤 첫 확인(스모크, `plan/00_구현핸드오프.md` 11장)

1. `.env`를 채우고 `docker compose up -d`, `set-admin-password`.
2. 분류: `docker compose exec worker flask --app run classify --limit 20 --redo` → 운영 화면 '분류·정리'에서 호출 기록·비용 확인. CLI 검증 결과와 class 일치율이 5%p 이상 낮으면 원인을 본다.
3. 표준 필드 API 보완: `docker compose exec worker flask --app run extract-fields --api --limit 10` → 비용 확인. 나머지 공모지원사업은 `extract-fields --api --batch` 뒤 `extract-fields --collect`.
4. 운영 화면 '자동화'에서 단계 스위치(첨부 글자·분류·표준 필드·API 보완)를 켠다.
5. 한 달 뒤 `llm_calls` 월 합계로 예산 상한(I-11)을 정한다.

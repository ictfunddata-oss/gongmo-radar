# 개요 및 문서 관리 규칙

## 1. 목적

「ICT기금 사용자 중심 AX서비스 구축 계획(안)」('26.6.24, 기금사업성과팀)의 **공모사업 파이프라인**을 실제로 구현하기 위한 설계 문서 모음이다. 크롤링(공고 수집)과 AI 기능(선별·분류)의 설계 방향, 개발 방식, 기능 정의를 한곳에서 관리하고, 개발이 진행되면 같은 문서를 개정해 누적한다.

> [!quote] AX계획 원문 (2. ICT기금 공모사업 파이프라인)
> (정보 수집) 주요 전담기관 및 유관 부처 홈페이지를 대상으로 실시간 웹 크롤링을 통한 공고 데이터의 주기적 자동 수집
> (AI기반 선별) 문맥 분석 기술을 활용해 일반 공지, 입찰, 타분야 사업 등을 구분하고 ICT기금 비R&D 사업공고만을 판별하여 추출
> (콘텐츠 지능형 분석) 공고 내용의 주요 정보를 자동 추출·요약하고 지원대상, 지원방식, 사업 분야 등으로 구조화 및 카테고리화

## 5. 문서 관리 규칙

> [!important] 누적 관리 원칙
> 문서는 지우지 않고 **개정**한다. 바뀐 내용은 D-90 개정 이력에, 설계 판단은 D-40 결정 기록에 남긴다.

| 항목 | 규칙 |
|---|---|
| 원본 | `설계(안)/docs/*.md`가 원본이다. `index.html`은 생성물이므로 직접 고치지 않는다 |
| 머리말 | 문서마다 `doc_id`·`title`·`group`·`version`·`status`·`updated`를 둔다 |
| 버전 | 내용 보완은 0.1 단위로 올리고, 담당자 검토를 거쳐 확정하면 1.0으로 올린다 |
| 상태 | `초안` → `검토` → `확정`. 확정 문서를 고치면 다시 `검토`로 내린다 |
| 기능 ID | `F-{영역}-{번호}`(예: F-SEL-03). 한 번 쓴 번호는 기능이 폐기돼도 재사용하지 않는다 |
| 기능 상태 | `구현` · `부분` · `시안` · `신규` · `검토` · `보류` · `폐기` 중 하나 |
| 결정·미결 | 결정은 `ADR-NNN`, 미결은 `I-NN`으로 번호를 붙이고 행을 지우지 않는다(상태만 바꾼다) |
| 개정 절차 | ① md 수정 → ② `version`·`updated` 갱신 → ③ D-90에 한 줄 추가 → ④ `python build_index.py` 실행 |

`build_index.py`는 실행할 때 기능 ID 중복, 머리말 누락, 개정 이력에 없는 버전을 찾아 경고한다.

# 데이터 설계

## 1. 현재 구조(NIPA PoC)

`nipa/data/nipa.db`(SQLite)의 테이블 3개다.

| 테이블 | 행 수('26.10.1) | 키 | 내용 |
|---|---|---|---|
| announcements | 353 | id(NIPA 게시물 번호) | 공고 원문·가공값·최초/최종 수집 시각 |
| attachments | 1,338 | (ann_id, seq) | 첨부 파일명·확장자·크기·URL |
| runs | 3 | run_id | 실행 방식·처리·신규·갱신·오류 건수, 로그 |

> [!warning] 기관을 늘리기 전에 바꿀 점
> 게시물 번호는 기관마다 따로 매겨지므로 `id` 하나로는 기관 간에 겹친다. 키를 (게시판, 게시물 번호)로 바꾸고 기관·게시판 테이블을 둔다.

## 3. 설계 규칙

| 규칙 | 내용 |
|---|---|
| 판정 이력 보존 | selections·classifications는 덮어쓰지 않고 실행마다 run_no를 올려 쌓는다. 최신값은 조회용 뷰로 제공 |
| 최종값 우선순위 | reviews(담당자) > 최신 AI·규칙 판정 |
| 원문·가공 분리 | 사이트 원문 값(period_raw 등)과 가공 값(start_at 등)을 따로 둔다 |
| 시각 표기 | ISO 8601(`2026-10-01T17:51:20`), 한국 시간 |
| 개인정보 | 작성자 이름은 내부 칼럼으로만 두고 외부 제공 데이터에서 뺀다 |

## 4. 이관 방안

| 순서 | 작업 |
|---|---|
| 1 | orgs·boards에 NIPA 사업공고 게시판 등록 |
| 2 | announcements를 새 구조로 복사(post_no = 기존 id, board_id = NIPA 사업공고) |
| 3 | attachments·runs의 키를 새 ann_id·board_id로 바꿔 복사 |
| 4 | 대시보드·성과지표 스크립트가 새 구조를 읽도록 수정하고, 이관 전후 건수(353·1,338·3) 대조 |

운영 DB(PIMS 쪽 등)로 옮길지는 PIMS 연계 방식(I-06)과 함께 정한다.

## 5. 배포 파이프라인 추가 표 (구현 2026-11-25, ADR-045·051)

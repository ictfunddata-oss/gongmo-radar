# 개발 절차

공모사업 웹크롤링(가칭 「공모사업 AI RADAR」)을 개발하는 데 필요한 절차와 현재까지의 진행 내용이다. 진행 내용은 대화·설계(안)·코드를 바탕으로 정리한 초안이며, 담당자가 검토해 고친다. 담당·일정 칸은 비워 둔다.

> [!note] 상태 표기
> 완료 / 진행 / 보류 / 미착수. 보류는 사용자가 구현을 미루기로 한 사항이다.

### 2.4 AI 판별 개발

| 항목 | 내용 |
|---|---|
| 목적 | 기금사업과 관련된 공모만 골라 노출하고, 지원 대상·방식·분야를 구조화한다 |
| 입력 | 공고 제목·본문, (정보 부족 건) 첨부 공고문 |
| 작업 | ① 제목 규칙 선별(결과 발표·설명회 등) ② AI 본문 판별(유형, 지원 대상·방식·분야, R&D 여부 등) ③ 노출 결정(`decide_exposure`) ④ 분류 체계 v1 → v1.2 개정, 프롬프트 `classify_v4` ⑤ Claude Code 판별 결과 가져오기 ⑥ 첨부 판독 시범 5건 |
| 산출물 | `app/ai/`(분류기, 스키마, 프롬프트), `app/services/rules.py`, 판별 기록 |
| 완료 기준 | |
| 관련 문서 | FS-SEL, FS-CLS, D-30 |

현재 판별 결과(첨부 시범 5건 반영 후)

| 구분 | 건수 |
|---|---|
| 노출 | 200 |
| 검토 | 38 |
| 제외 | 115 |
| 합계 | 353 |

- 노출 결정: 공고 유형이 '사업 모집'이면 노출, 사업 모집이 아니거나 R&D 사업이면 제외, R&D 미확인·확신 낮음·기타는 검토.
- 정확도(정답 표본 대비)는 측정하지 않는다. 점진 개정 방식으로 결과를 보고 하나씩 고친다(ADR-015).
- 보류: 첨부 판독의 선별 단계 통합(대상 148건, 그중 공고문류 139건). 내역사업 대조(F-SEL-03·04)는 목록 확보 전이라 미착수.

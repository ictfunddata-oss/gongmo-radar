# 설계 방향

## 1. 목표 구조

공고 한 건이 수집부터 서비스까지 거치는 흐름이다. 각 단계는 앞 단계의 저장 결과만 읽으므로 따로 다시 돌릴 수 있다. 예를 들어 분류 기준이 바뀌면 수집을 다시 하지 않고 분류 단계만 재실행한다.

<div class="flow">
  <div class="step"><b>① 수집</b><span>기관 어댑터가 목록·상세를 읽음</span><em>FS-CRW</em></div>
  <div class="step"><b>② 정규화 저장</b><span>공통 구조로 DB 저장</span><em>D-20</em></div>
  <div class="step"><b>③ 선별</b><span>규칙 → 내역사업 대조 → AI</span><em>FS-SEL</em></div>
  <div class="step"><b>④ 분류·추출</b><span>유형·분야·지원정보 구조화</span><em>FS-CLS</em></div>
  <div class="step"><b>⑤ 검수</b><span>확신 낮은 건 담당자 확인</span><em>FS-SVC</em></div>
  <div class="step"><b>⑥ 서비스</b><span>현황판·조회·PIMS 연계</span><em>FS-SVC</em></div>
</div>

| 단계 | 입력 | 출력 | 실행 시점 |
|---|---|---|---|
| ① 수집 | 기관 게시판 URL | 공고 원문(제목·기간·본문·첨부 목록) | 매일 1회(증분) |
| ② 정규화 저장 | 원문 | 공통 스키마의 공고 행 | 수집 직후 |
| ③ 선별 | 공고 행 + 내역사업 목록 | 공고 유형, 기금·R&D 구분, 노출 여부 | 신규·변경 공고 발생 시 |
| ④ 분류·추출 | 노출 대상 공고 | 수혜자 유형, 지원방식, 사업분야, 지원정보 요약 | 선별 직후 |
| ⑤ 검수 | 확신 낮은 판정 | 담당자 확정값 | 주 1회 또는 수시 |
| ⑥ 서비스 | 확정·자동 판정 결과 | 현황판, 조회 화면, 내보내기 | 상시 |

## 2. 설계 원칙

| 번호 | 원칙 | 적용 |
|---|---|---|
| P1 | **규칙으로 정할 수 있는 것은 규칙으로** | 입찰·결과 발표처럼 제목만으로 갈리는 공고와 기금 여부(내역사업 대조)는 AI를 쓰지 않는다. AI는 애매한 건과 본문 이해가 필요한 분류에만 쓴다 |
| P2 | **AI 판정은 재현 가능하게** | 모든 판정에 모델명·프롬프트 버전·분류 체계 버전·근거 문장을 함께 저장한다 |
| P3 | **사람 판정이 우선** | 담당자가 고친 값은 AI 재실행으로 덮어쓰지 않는다. 고친 값은 검증 데이터로 쌓는다 |
| P4 | **원천 보존** | 원문 URL, 최초·최종 수집 시각, 사이트 원문 값을 지우지 않는다. 가공값은 별도 칸에 둔다 |
| P5 | **기관 추가는 어댑터 추가로** | 저장 구조·선별·분류는 기관과 무관하게 만든다. 새 기관은 어댑터 파일 하나로 붙인다 |
| P6 | **준법 수집** | robots.txt 준수, 요청 간격 0.3초 이상, 개인정보(담당자 연락처 등) 미수집 |
| P7 | **공급자 교체 가능** | AI 호출부를 한 모듈로 모아, 모델·공급자를 바꿔도 선별·분류 로직은 그대로 둔다 |

## 3. 핵심 설계 판단

> [!tip] 기금·비R&D 판정은 AI가 아니라 기준표 대조
> NIPA 공고 353건을 보면 공고문에 재원(기금·일반회계)이나 R&D 구분이 거의 적혀 있지 않다. 반면 상세 페이지의 사업구분 칸이 99.2%(350/353건) 채워져 있어 내역사업명 역할을 한다. 그래서 사업구분 → 내역사업 → 기금·R&D 구분을 기준표로 대조하고, 기준표에 없는 사업만 AI가 추정한 뒤 담당자가 확인한다(ADR-003).

> [!tip] 공고가 아니라 사업 단위로 보여 준다
> 같은 사업이 본공고·수정공고·추가모집·결과 공지로 여러 번 게시된다(예: 'ICT창의기업육성' 36건). 수요자 화면은 사업 하나를 카드 하나로 보여 주고 공고 이력을 그 안에 묶는다(F-CLS-06).

> [!warning] 내용이 첨부에만 있는 공고
> NIPA 공고의 27.5%(97/353건)는 본문이 50자 미만이고 내용이 첨부(hwp·pdf)에 있다. 첨부 저장은 보류 중이므로, 1차 PoC에서는 이런 공고를 '정보 부족'으로 표시하고 정확도를 따로 집계한다(I-04).

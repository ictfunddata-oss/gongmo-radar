### F-SVC-08 PIMS 연계

| 방식(후보) | 장점 | 단점 |
|---|---|---|
| 파일 제공(주기적 엑셀·JSON) | 가장 단순, 보안 검토 부담 적음 | 실시간성 낮음 |
| PIMS가 읽는 조회 API | PIMS 화면에서 바로 최신 데이터 | API 서버 운영 필요 |

AX계획의 "공모사업은 별도페이지 제작 후 데이터 연계"에 따라 PIMS 쪽 화면은 별도로 만들고, 이 과제는 데이터 제공 방식까지 정한다.

## 3. 화면 공통 규칙

| 규칙 | 내용 |
|---|---|
| 언어 | 화면 문구는 모두 한글 |
| 접수 상태 | 페이지를 연 시각 기준으로 계산. 제목에 '[접수마감]'이 있으면 기간과 관계없이 마감 |
| 상시 모집 | 신청기간이 없고 게시 1년 이내면 '상시 모집', 1년이 지나면 '접수 마감' |
| 개인정보 | 수요자 화면에 작성자(담당자 이름)를 표시하지 않음 |
| 접수 진행 막대 | 목록 카드에는 신청 기간 글자 아래의 진행 막대를 표시하지 않는다(ADR-030). 신청 기간 문구와 D-day 배지로 충분하다고 판단. 상세 화면의 막대는 그대로 |
| 사업명 줄 | 카드·상세에 '사업명 · ○○' 줄을 표시하지 않는다(ADR-025). 기관마다 사업구분 칸이 달라 NIA는 제목의 말머리가 들어가 사업명이 아니었다. 값(`biz`)은 저장하고 검색에는 계속 쓴다 |
| 분류 출처 표시 | 수요자 화면에는 'AI 분류'·'임시 분류' 같은 출처 표시를 하지 않는다(ADR-020). 신청 자격·일정은 원문 확인 안내만 둔다 |
| 출처 | 모든 공고에 원문 링크 제공 |

※ 위 규칙은 UI 시안 제작 중 정한 것이다('26.10.2). 시안 적용은 보류(ADR-006)지만 규칙은 화면 개발 시 그대로 쓴다.

## 4. 목록 화면 서비스 규칙

수요자 목록 화면(`/`)에 얹은 작은 서비스의 기준이다. 시안은 `docs/UI_디자인(안)/시각화/목록화면_서비스추가.html`이고 구현은 `app/static/public.js`·`app/services/public.py`다. 기준을 바꾸면 이 절과 설정값을 함께 고친다.

### 4.1 곧 마감 띠 (F-SVC-12)

| 항목 | 규칙 |
|---|---|
| 대상 | 접수 상태가 '마감 임박' 또는 '접수 중'인 공고. 상시 모집·접수 예정·접수 마감은 제외 |
| 조건 | 마감까지 남은 일수(오늘 포함, 마감일 당일은 0일)가 `PUBLIC_SOON_DAYS`(기본 30일) 이하 |
| 정렬·건수 | 남은 일수가 적은 순, 같으면 마감 일시가 빠른 순. 최대 `PUBLIC_SOON_MAX`(기본 10건) |
| 표시 | D-day, 제목(두 줄까지), 기관, 마감일. 남은 일수 3일 이하는 빨강 강조 |
| 필터와의 관계 | 아래 목록의 필터·검색과 무관하게 전체 공고에서 뽑는다 |
| 대상이 없을 때 | 띠를 숨긴다 |

### 4.2 NEW 배지 (F-SVC-13)

| 항목 | 규칙 |
|---|---|
| 기준 | 게시일(없으면 목록의 작성일)이 오늘 포함 `PUBLIC_NEW_DAYS`(기본 7일) 이내. 7일 전 날짜는 해당하지 않음 |
| 제외 | 게시일이 오늘보다 미래이거나 없으면 표시하지 않음 |
| 접수 상태와 관계 | 상태(마감 등)와 무관하게 게시일만 본다 |
| 계산 위치 | 서버(`is_new`). 수집일(`first_seen`)이 아니라 게시일을 쓴다 — 한꺼번에 수집한 공고가 모두 NEW가 되는 것을 막기 위함 |

### 4.3 분야 분포 막대 (F-SVC-14)

| 항목 | 규칙 |
|---|---|
| 대상 | 왼쪽 필터의 '지원 분야' 묶음만. 다른 묶음에는 붙이지 않음 |
| 길이 | 현재 필터를 반영한 분야별 건수(항목 옆 숫자와 같은 값)를 그 묶음의 최대 건수 대비 비율로 그린다. 최대값이 표시 폭의 78% |
| 최소 폭 | 건수가 1건 이상이면 4% 이상, 0건이면 막대를 그리지 않음 |
| 한 공고가 여러 분야 | 공고가 가진 모든 분야에 각각 센다(합계가 전체 건수보다 클 수 있음) |

### 4.4 관심 공고 저장 (F-SVC-15)

| 항목 | 규칙 |
|---|---|
| 저장 위치 | 이용자 브라우저 `localStorage`의 `gongmoFavs`(공고 번호 배열). 서버에는 보내지 않고 계정·개인정보를 쓰지 않음 |
| 저장소를 쓸 수 없을 때 | 오류 없이 동작하고 이번 방문 동안만 유지 |
| 건수 | 지금 목록에 있는 공고만 센다. 노출에서 빠진 공고의 번호는 남아 있어도 세지 않음 |
| 보기 | '관심 공고만 보기'는 다른 필터와 함께 적용(AND). 상단 메뉴에 건수 표시(0건이면 숨김) |
| 한계 | 다른 브라우저·기기와 공유되지 않고 브라우저 데이터를 지우면 사라진다. 이메일·알림 연계는 하지 않음 |

### 4.5 목록 쪽 번호 이동 (F-SVC-16)

| 항목 | 규칙 |
|---|---|
| 쪽 크기 | 12건 |
| 막대 | 처음·이전·번호·다음·마지막. 번호는 처음, 마지막, 현재 앞뒤 2쪽을 보이고 사이는 '…' |
| 위치 | 목록 위와 아래 두 곳에 같은 막대 |
| 초기화 | 필터·검색·정렬·통계 카드·조건 초기화를 바꾸면 1쪽으로 돌아감 |
| 쪽 이동 | 번호를 누르면 목록 맨 위로 이동. 쪽이 1개뿐이면 막대를 숨김 |

| 항목 | 규칙 |
|---|---|
| 배지 색 | 기관 코드별 고정 번호(NIPA 0, NIA 1). 새 기관은 코드 문자 합으로 2~5번 색을 받음 |
| 필터 | 노출 공고에 기관이 둘 이상일 때만 '기관' 묶음을 보여 줌. 검색어에도 기관명 포함 |
| 노출 기준 | 기관과 무관하게 같은 노출 규칙(사업 모집만)을 적용. 입찰·용역은 제외(ADR-023) |

### 4.7 많이 찾는 검색어 (F-SVC-18)

| 항목 | 규칙 |
|---|---|
| 기록 시점 | 이용자가 검색창에 입력을 멈추고 1.5초가 지났을 때, 검색 버튼을 눌렀을 때, Enter를 눌렀을 때. 같은 방문(탭)에서 같은 검색어는 한 번만 기록 |
| 기록하지 않는 것 | '많이 찾는 검색어' 칩을 눌러 한 검색, 2자 미만·30자 초과, 이메일·전화번호·인터넷 주소로 보이는 값, **금칙어가 들어 있는 검색어**(아래) |
| 저장 항목 | 검색어(공백 정리), 소문자로 맞춘 값, 그때 화면에 나온 결과 건수, 검색 일시(`search_logs`). **검색한 사람은 저장하지 않음**(IP·계정·브라우저 정보 없음) |
| 보관 기간 | 180일. 새 기록을 쓸 때 오래된 기록을 지움 |
| 집계 | 최근 `PUBLIC_POPULAR_DAYS`(기본 30일) 동안 **결과가 1건 이상 나온** 검색어를 대소문자 구분 없이 묶어 센다. 표기는 가장 많이 쓰인 것으로 보여 줌 |
| 표시 조건 | `PUBLIC_POPULAR_MIN`(기본 2회) 이상 검색된 것만, 많은 순으로 최대 `PUBLIC_POPULAR_MAX`(기본 5개). 횟수가 같으면 최근에 검색된 것이 앞섬 |
| 기록이 없을 때 | 줄 전체를 숨김(고정 검색어를 대신 보여 주지 않음) |
| 금칙어 | `app/banned_terms.txt`(설정 `BANNED_TERMS_PATH`). 한 줄에 한 단어, `#`은 설명, `!`로 시작하면 예외 단어. 파일을 고치면 서버를 다시 켜지 않아도 바로 적용 |
| 금칙어 검사 방식 | 검색어와 금칙어 모두 소문자로 바꾸고 한글·영문·숫자·자모만 남겨(공백·기호 제거) 비교한다. 검색어에 금칙어가 **포함**되면 걸림('시 발', '시.발', 'Fuck', 'ㅅㅂ' 모두 해당). 예외 단어는 먼저 빼고 나머지로 검사('시발점'은 통과) |
| 금칙어 적용 범위 | ① 기록하지 않음 ② 이미 기록된 것도 집계·표시에서 뺌(반복 횟수가 많아도 보이지 않음. 목록을 늘리면 기존 기록에도 바로 적용) ③ **검색 자체는 막지 않음** — 이용자가 입력하면 결과는 그대로 나옴 |
| 금칙어 목록 구성 | 욕설, 초성·자모 줄임말, 선정적 표현, 비하·혐오 표현. 공백을 없애고 검사하므로 다른 단어의 일부로 우연히 겹치는 짧은 단어는 넣지 않는다(예: '구성기관'의 '성기', '애자일'의 '애자', '한-일 베트남'의 '일베'). 수집한 공고 제목 전체가 걸리지 않는지 시험으로 확인 |
| 한계 | 한 사람이 여러 방문(탭)에서 같은 단어를 반복하면 횟수가 늘어난다. 기록이 적은 초기에는 비어 있을 수 있다. 목록은 완전하지 않으며(새로운 은어·변형은 담당자가 추가), 글자를 바꿔 쓰거나(예: 'ㅅ1ㅂ') 풀어 쓰는 변형은 걸러지지 않을 수 있다 |
| 활용 | 같은 기록으로 관리자 화면의 검색 키워드 통계(보류 중)를 만들 수 있다 |

### 4.8 금칙어 관리 화면 (F-SVC-19)

| 항목 | 규칙 |
|---|---|
| 위치 | 운영 화면 `/admin/banned`(상단 '금칙어 관리') |
| 저장 | 별도 테이블이 아니라 금칙어 파일(`app/banned_terms.txt`)을 직접 고친다. 화면에서 추가한 단어는 파일 끝 `관리자 화면에서 추가` 구역에 들어가고, 기존 설명·단어는 그대로 보존. 추가·삭제 때마다 직전 상태를 `.bak`으로 백업. 바뀐 목록은 서버를 다시 켜지 않아도 수요자 화면에 바로 적용 |
| 금칙어 추가 | 공백·기호를 뺀 글자가 2자 이상 30자 이하. 이미 있는 단어(공백이 달라도 같은 단어)는 거절. **수집한 공고 제목에 그 단어가 들어 있으면 경고하고 저장하지 않는다**(정상 검색어를 가릴 수 있음). '그래도 추가'를 체크해야 저장 |
| 예외 단어 | 금칙어가 정상 단어의 일부로 걸릴 때 추가한다. 같은 방식으로 추가·삭제 |
| 삭제 | 단어 옆 ×를 누르고 확인하면 삭제. 기본 단어와 관리자 추가 단어 모두 삭제할 수 있음 |
| 검색어 점검 | 입력한 검색어가 걸리는지, 어떤 금칙어에 걸렸는지 보여 줌(저장하지 않음) |
| 최근 검색어 | 최근 `PUBLIC_POPULAR_DAYS`일 검색어를 많은 순으로(최대 50개) 보여 줌. 결과가 0건이었던 검색어와 금칙어도 포함. 상태: **금칙어**(걸림) / **표시 중**(결과 있는 검색이 `PUBLIC_POPULAR_MIN`회 이상) / **대기**. 행마다 '금칙어로 추가' 버튼 |
| 접근 제어 | 관리자 로그인이 필요하다(F-SVC-20, §4.9). 로그인하지 않은 요청은 추가·삭제도 처리되지 않음 |

### 4.9 관리자 로그인 (F-SVC-20)

| 항목 | 규칙 |
|---|---|
| 보호 대상 | `/admin/` 아래 모든 화면·쓰기 요청, 운영용 API(`/api/announcements`, `/api/announcements/<id>`, `/api/stats`). 열려 있는 것: 수요자 화면 `/`, 공고 상세 `/notice/…`, 공개 API `/api/public/announcements`, 검색어 기록 `/search-log` |
| 계정 | 관리자 1명(아이디 `ADMIN_ID`, 기본 `admin`). 기관 계정(SSO) 연동은 하지 않음 — 필요하면 별도 결정 |
| 비밀번호 | **해시로만 저장**(`.env`의 `ADMIN_PASSWORD_HASH`). 코드·문서·화면에 평문을 두지 않는다. 설정은 `flask --app run set-admin-password`(10자 이상, 입력은 화면에 보이지 않음). `--generate`는 무작위 비밀번호를 만들어 `data/admin_initial_password.txt`에만 기록하고 화면에 출력하지 않음 — 로그인한 뒤 바꾸고 그 파일을 지운다 |
| 서명 키 | 세션 쿠키 서명용 `SECRET_KEY`가 기본값이거나 32자 미만이면 설정 명령이 무작위 값으로 바꿈 |
| 세션 | 서명된 세션 쿠키(HttpOnly, SameSite=Lax). `ADMIN_SESSION_HOURS`(기본 8시간) 뒤 만료. 로그아웃 버튼(`POST /admin/logout`)은 쿠키를 지움. https로 배포하면 `ADMIN_COOKIE_SECURE=true` |
| 비밀번호가 설정되지 않았을 때 | 운영 화면은 열리지 않고(503) 설정 방법을 안내한다. 열려 있는 채로 두지 않는다 |
| 로그인 실패 제한 | 같은 접속 주소에서 10분 안에 5번 실패하면 10분간 로그인을 막음(맞는 비밀번호도 거절). 실패할 때마다 0.4초 지연. 서버를 다시 켜면 초기화 |
| 로그인 뒤 이동 | `next` 주소는 이 사이트의 `/admin` 아래 경로만 허용 |
| CSRF | 쓰기 요청은 모두 POST이고 쿠키가 SameSite=Lax라서 다른 사이트에서 보낸 요청에는 로그인 쿠키가 실리지 않음. 별도 토큰은 아직 없음 |
| 한계 | 실패 횟수가 서버 메모리에만 있어 서버를 여러 대로 늘리거나 다시 켜면 공유·유지되지 않는다. 비밀번호 분실 시 설정 명령을 다시 실행한다. 감사 기록(누가 언제 무엇을 바꿨는지)은 아직 없음 |

### 4.12 선별 규칙 화면 (F-SVC-24, F-SEL-09)

| 항목 | 규칙 |
|---|---|
| 접근 | 로그인한 관리자만(`/admin/rules`) |
| 규칙 구성 | 이름, 적용 게시판(전체 또는 하나), 검사 대상(제목 / 말머리=사업구분), 방식(단어 포함 / 정규식), 찾을 단어, 예외 단어, 결과 유형, 사용 여부, 메모 |
| 결과 유형 | 제외 유형(입찰·용역, 입주 모집, 행사·전시 참가, 경진대회·공모전·포상, 결과 발표, 설명회·안내)만. 사업 모집으로 확정하는 규칙은 만들 수 없음(애매하면 AI가 판단 — 원칙 P1) |
| 검사 순서 | 목록 순서대로 검사해 처음 걸리는 규칙을 씀. 예외 단어가 함께 있으면 그 규칙은 건너뜀 |
| 입력 검증 | 정규식 오류, 1글자 단어, 모든 공고에 걸리는 식(빈 글자에도 맞는 정규식)은 저장 거절 |
| 영향 확인 | 목록에 규칙별로 '현재 공고 적중 건수 · 판별 전 건수 · 이미 다르게 판별된 건수(그중 노출 중)'와 예시를 보여 줌. 다르게 판별된 건수가 많으면 규칙이 너무 넓다는 신호 |
| 적용 범위 | 아직 판별하지 않은 공고에만 적용. 이미 판별된 결과는 바꾸지 않음. 적용 시점: 판별 시(`classify`), 자동화 ②단계, 화면의 '판별 전 공고에 지금 적용'(AI 호출 없음) |
| 시험 | 제목·말머리·게시판을 넣어 어느 규칙에 걸리는지 저장 없이 확인 |
| 기본 규칙 | 처음 한 번만 넣음: 결과 발표(제목), 설명회·안내(제목), NIA 입찰 말머리(조달·입찰·사전규격·사전공개 → 입찰·용역), NIA 검토결과 공개(→ 설명회·안내). 지우면 다시 살아나지 않음 |
| 한계 | 규칙 변경 이력은 남기지 않음(이름·수정 시각만). 규칙은 제목·말머리만 봄(본문 검사 없음). 같은 공고가 AI 판별로 이미 처리됐다면 규칙을 고쳐도 되돌리지 않음 |

### 4.13 공고 유형 필터 (F-SVC-29, ADR-047)

| 항목 | 규칙 |
|---|---|
| 기본 선택 | 공모지원사업만 보인다. 입찰공고·기타는 필터에서 켜면 보인다 |
| 유형 값 | 분류 결과(announcement_labels, D-20 §5)의 class. 사람이 고친 값을 먼저 쓴다 |
| 분류 전 공고 | '미분류' 배지를 달아 기본 목록에 넣는다(ADR-052). 기본 선택('공모지원사업')에 함께 보이고, '미분류'만 따로 고를 수도 있다 |
| 배지 | 카드와 상세에 유형 배지를 단다. 하위 유형(입찰·사전규격·참가·교육 등)은 상세에만 표시한다 |
| 건수 | 접수 상태 필터처럼 유형별 건수를 버튼에 보여 준다 |
| 수집 | 입찰공고도 계속 수집한다(I-10) |

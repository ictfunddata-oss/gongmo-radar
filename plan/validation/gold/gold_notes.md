## 판정 규칙 결정 (2026-11-26)

W-gold가 검수 요청한 항목을 사용자 위임으로 코디네이터(Claude)가 정했다. 정답표 줄은 바꾸지 않았다. 사람 검수가 아니므로 `reviewed`는 모두 `false` 그대로이고, 지표는 계속 '잠정'이다.

| 항목 | 결정 | 근거 |
|---|---|---|
| 규칙 3 — 입찰공고 content key를 건명으로 | **유지** | 핸드오프 4.2가 입찰 '공고 내용'을 '입찰건명 + 사업 개요 + 예산·기간'으로 정했고, 규칙 추출도 '건명: … / 기간: … / 예산: …' 꼴로 낸다. 판별력이 약한 점은 알고 둔다. 입찰공고는 API 보완 대상이 아니라 이 칸의 지표가 프롬프트 판단에 쓰이지 않는다 |
| 규칙 5 — NIA·KCA 사전규격의 area를 계약방법으로 대신 | **유지** | 4.2가 입찰 '분야'를 '게시판 분류 + 계약방법(대체값)'으로 정했다. 말머리뿐인 biz는 분야 정보가 아니다 |
| 규칙 6 — NIA 입찰 period를 사이트 공고기간으로 | **유지** | 4.4 출처 우선순위(사이트 칸 > 본문 > 첨부)와 같고, 마감일은 실제 제안서 접수 마감과 같다. 접수 상태 계산(`services/public.status`)도 사이트 기간을 쓴다. 실제 접수 시작일은 memo에 남아 있다 |
| 공고 352 — 연구개발과제 공동연구기관 공모 | **입찰공고 유지** | v2 규칙 3: '위탁연구·연구과제 공모는 협약 체결·연구비 지원 단서가 있어도 입찰공고(협상공모)'. v2 CLI 실행은 공모지원사업으로 냈으나 규칙 문장에 따르면 입찰공고가 맞다 |
| 공고 840 — 공정채용 우수기업 어워즈 | **공모지원사업(참가·교육) 유지** | 응모 대상·응모 유형·접수 기간이 있는 공모이고 선정되면 시상을 받는다(규칙 1·5). 규칙 8의 '유공자 포상'은 기관이 추천·선정하는 포상 안내를 뜻하는 것으로 본다. 관문 2 표본 18건(2026-11-26 확정)도 이 판단을 전제로 한다 |
